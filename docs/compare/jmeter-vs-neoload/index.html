JMeter vs NeoLoad

NeoLoad is a commercial load testing tool, owned by Tricentis since it bought Neotys in 2021. JMeter is the free, open-source standard. Both are GUI-first. The choice comes down to protocols, how much time correlation costs you, and budget.

Facts checked November 2026. Written by Pawan Sinha, who has used JMeter, LoadRunner, k6 and Gatling on banking, payments and lottery projects.

The short answer

Which one should you pick?

Pick JMeter if…

  • You mainly test websites and HTTP APIs.
  • There is no licence budget, or you want to run tests freely in CI without counting virtual users.
  • Your team is comfortable supporting an open-source tool and its plugins themselves.
  • You need JDBC, LDAP, mail or raw TCP tests.

Pick NeoLoad if…

  • You must test SAP GUI, Citrix or Oracle Forms.
  • Recording and correlating complex web apps takes too long by hand, and automatic correlation would pay for itself.
  • You want shared dashboards, run comparisons and APM integrations in one product.
  • You want a vendor to call when something breaks, or you already use other Tricentis tools.

Same test, two tools

A 50-user load test in each

The same simple test in both: load the home page, check for a 200 response, ramp up to 50 users over a minute, then hold for three minutes with one second of think time.

JMeter (.jmx)

<!-- Trimmed: the parts of a .jmx file that matter -->
<ThreadGroup testclass="ThreadGroup" testname="Users">
  <intProp name="ThreadGroup.num_threads">50</intProp>
  <intProp name="ThreadGroup.ramp_time">60</intProp>
  <boolProp name="ThreadGroup.scheduler">true</boolProp>
  <stringProp name="ThreadGroup.duration">240</stringProp>
</ThreadGroup>
<hashTree>
  <HTTPSamplerProxy testclass="HTTPSamplerProxy" testname="Home page">
    <stringProp name="HTTPSampler.protocol">https</stringProp>
    <stringProp name="HTTPSampler.domain">test.example.com</stringProp>
    <stringProp name="HTTPSampler.path">/</stringProp>
    <stringProp name="HTTPSampler.method">GET</stringProp>
  </HTTPSamplerProxy>
  <hashTree>
    <ResponseAssertion testclass="ResponseAssertion" testname="Status is 200">
      <collectionProp name="Asserion.test_strings">
        <stringProp name="49586">200</stringProp>
      </collectionProp>
      <stringProp name="Assertion.test_field">Assertion.response_code</stringProp>
      <intProp name="Assertion.test_type">8</intProp>
    </ResponseAssertion>
  </hashTree>
  <ConstantTimer testclass="ConstantTimer" testname="Think time">
    <stringProp name="ConstantTimer.delay">1000</stringProp>
  </ConstantTimer>
</hashTree>

You normally build this in the GUI: a Thread Group (50 threads, 60 s ramp-up, 240 s duration), an HTTP Request sampler, a Response Assertion on the response code and a Constant Timer. Run it without the GUI: jmeter -n -t plan.jmx -l results.jtl -e -o report/. (Yes, Asserion is spelt that way in JMeter itself.)

NeoLoad as code (YAML, sketch)

# NeoLoad "as code" (YAML). A sketch: check the field
# names against the as-code docs for your NeoLoad version.
name: home-page
servers:
- name: site
  host: test.example.com
  scheme: https
user_paths:
- name: visitor
  actions:
    steps:
    - transaction:
        name: Home page
        steps:
        - request:
            server: site
            url: /
    - delay: 1s          # think time
populations:
- name: visitors
  user_paths:
  - name: visitor
scenarios:
- name: load-50
  populations:
  - name: visitors
    rampup_load:
      min_users: 5
      max_users: 50
      increment_users: 5
      increment_every: 6s
      duration: 4m

Most NeoLoad tests are recorded and built in the NeoLoad GUI, with automatic correlation. The YAML "as code" format suits CI and can be combined with a GUI project. Response checks and SLA profiles (pass/fail thresholds) are added in the GUI or the same file. You run it from NeoLoad Web or the NeoLoad CLI.

Switching

Moving between JMeter and NeoLoad

  1. List what you have: scripts, protocols, how often each runs and who owns it. SAP GUI, Citrix and Oracle Forms tests are the hard ones to move to JMeter.
  2. There is no reliable automatic converter either way. Re-record each journey and rebuild the correlation. A browser HAR file is a good shared starting point.
  3. Keep the same transaction names, so new results can be compared with your old baselines.
  4. Run the old and new tests once at the same load and investigate any gap before you switch.
  5. Moving off a commercial tool for HTTP work anyway? Look at k6 too, and the JMeter → k6 converter.

FAQ

Common questions

Is NeoLoad free?

NeoLoad is commercial. Tricentis has offered trials and limited free editions over the years, so check its site for what is available now.

Who owns NeoLoad?

Tricentis. It bought Neotys, the company that built NeoLoad, in 2021.

Can JMeter replace NeoLoad?

For websites and HTTP APIs, usually yes, at the cost of more manual correlation. For SAP GUI, Citrix or Oracle Forms, usually not.

Is NeoLoad only for web applications?

No. Besides websites and APIs it covers packaged-application protocols such as SAP GUI, Citrix and Oracle Forms, which is a common reason teams pay for it.
