JMeter vs LoadRunner

LoadRunner is the long-standing commercial tool, now sold by OpenText under the Performance Engineering name. JMeter is the free, open-source alternative. The choice usually comes down to protocols, budget and support.

Facts checked November 2026. Written by Pawan Sinha, who has used JMeter, LoadRunner, k6 and Gatling on banking, payments and lottery projects.

The short answer

Which one should you pick?

Pick JMeter if…

  • You mainly test websites and HTTP APIs.
  • There is no licence budget, or you want to run tests on every build without counting virtual users.
  • You want to run tests in CI pipelines and containers freely.
  • Your team is comfortable supporting an open-source tool themselves.

Pick LoadRunner if…

  • You must test Citrix, SAP GUI, Oracle Forms, RDP or terminal (mainframe) applications.
  • You want automatic correlation and a vendor to call when something breaks.
  • You need deep analysis that lines up response times with server monitors in one place.
  • Your organisation already owns licences and has trained people.

Same test, two tools

A 50-user load test in each

The same simple test in both: load the home page, check for a 200 response, ramp up to 50 users over a minute, then hold for three minutes with one second of think time.

JMeter (.jmx)

<!-- Trimmed: the parts of a .jmx file that matter -->
<ThreadGroup testclass="ThreadGroup" testname="Users">
  <intProp name="ThreadGroup.num_threads">50</intProp>
  <intProp name="ThreadGroup.ramp_time">60</intProp>
  <boolProp name="ThreadGroup.scheduler">true</boolProp>
  <stringProp name="ThreadGroup.duration">240</stringProp>
</ThreadGroup>
<hashTree>
  <HTTPSamplerProxy testclass="HTTPSamplerProxy" testname="Home page">
    <stringProp name="HTTPSampler.protocol">https</stringProp>
    <stringProp name="HTTPSampler.domain">test.example.com</stringProp>
    <stringProp name="HTTPSampler.path">/</stringProp>
    <stringProp name="HTTPSampler.method">GET</stringProp>
  </HTTPSamplerProxy>
  <hashTree>
    <ResponseAssertion testclass="ResponseAssertion" testname="Status is 200">
      <collectionProp name="Asserion.test_strings">
        <stringProp name="49586">200</stringProp>
      </collectionProp>
      <stringProp name="Assertion.test_field">Assertion.response_code</stringProp>
      <intProp name="Assertion.test_type">8</intProp>
    </ResponseAssertion>
  </hashTree>
  <ConstantTimer testclass="ConstantTimer" testname="Think time">
    <stringProp name="ConstantTimer.delay">1000</stringProp>
  </ConstantTimer>
</hashTree>

You normally build this in the GUI: a Thread Group (50 threads, 60 s ramp-up, 240 s duration), an HTTP Request sampler, a Response Assertion on the response code and a Constant Timer. Run it without the GUI: jmeter -n -t plan.jmx -l results.jtl -e -o report/. (Yes, Asserion is spelt that way in JMeter itself.)

LoadRunner VuGen (C)

Action()
{
    int status;

    lr_start_transaction("home_page");

    web_url("home_page",
        "URL=https://test.example.com/",
        "Resource=0",
        "Mode=HTML",
        LAST);

    status = web_get_int_property(HTTP_INFO_RETURN_CODE);

    if (status == 200)
        lr_end_transaction("home_page", LR_PASS);
    else
        lr_end_transaction("home_page", LR_FAIL);

    lr_think_time(1);
    return 0;
}

A VuGen script in C (Web HTTP/HTML protocol). The 50 users, the ramp and the duration are not in the script: you set them in the scenario schedule in the Controller (or in Enterprise Performance Engineering).

Switching

Moving off LoadRunner

  1. List what you have first: scripts, protocols, how often each runs and who owns it. Anything on Citrix, SAP GUI or terminal protocols may need to stay on LoadRunner.
  2. There is no reliable automatic LoadRunner-to-JMeter converter. Re-record each journey (JMeter's HTTP(S) Test Script Recorder, or a browser HAR file) and rebuild the correlation.
  3. Keep the same transaction names, so the new results can be compared with your LoadRunner baselines.
  4. Run the old and new tests once at the same load. Investigate any gap before you switch.
  5. If you're choosing a new tool anyway, look at k6 too: you can convert JMeter plans later with the JMeter → k6 converter.

FAQ

Common questions

Is LoadRunner free?

Not for real use. OpenText includes a free Community licence of 50 virtual users for most protocols, which is fine for learning and small trials. Bigger tests need paid licences.

What happened to LoadRunner?

Nothing has been discontinued. OpenText (which bought Micro Focus) renamed the products in 2025: LoadRunner Professional is now OpenText Professional Performance Engineering, Enterprise is Enterprise Performance Engineering and Cloud is Core Performance Engineering.

Can JMeter replace LoadRunner?

For websites and HTTP APIs, usually yes. For Citrix, SAP GUI, Oracle Forms or terminal applications, usually not.

Do banks still use LoadRunner?

Many large organisations still do, often alongside JMeter or k6 for newer HTTP and API work.
