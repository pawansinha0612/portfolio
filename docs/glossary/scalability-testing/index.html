What is Scalability testing?

Scalability testing measures how throughput and response time change as you add resources such as pods, servers or database replicas, to show whether the system actually scales.

Why it matters

Adding servers only helps if the work can spread across them. A shared database, a lock or a single-threaded component can mean that doubling the servers adds 20% more capacity, or none.

An example

One pod handles 150 requests a second. Two pods handle 290 and four pods handle 520, so far so good. Eight pods handle 560, because every pod now competes for the same 100 database connections. The limit is the database, not the app.

How to measure or test it

Run the same breakpoint test at 1, 2, 4 and 8 instances and plot maximum throughput against instance count. A straight line is linear scaling. A curve that flattens points to a shared bottleneck.

Common mistakes

  • Assuming results from a small environment can be multiplied up to production size.
  • Scaling the app tier without checking what it does to the database and downstream services.
