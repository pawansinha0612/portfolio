What is Load testing?

Load testing checks how a system behaves under the traffic you expect at peak, to prove it meets its response time and error targets before real users arrive.

Why it matters

Most outages at big moments are not bugs. They are capacity problems: a connection pool that runs dry, a slow query that only hurts at volume, an autoscaler that reacts too late. A load test finds these on your schedule instead of your customers' schedule.

An example

An online shop expects 40 orders a minute on Black Friday, which works out to about 120 API requests a second at the busiest minute. A load test holds 120 requests a second for 30 minutes and checks that p95 stays under 800 ms and errors stay under 1%.

How to measure or test it

Model real traffic (which pages, in what mix, at what rate), run it against a production-like environment, and watch response time percentiles, error rate and throughput alongside server metrics such as CPU, memory and database connections.

export const options = {
  scenarios: {
    peak: { executor: 'constant-arrival-rate', rate: 120, timeUnit: '1s',
            duration: '30m', preAllocatedVUs: 200 },
  },
  thresholds: { http_req_duration: ['p(95)<800'], http_req_failed: ['rate<0.01'] },
}

Common mistakes

  • Testing one URL in a loop instead of the real mix of user journeys.
  • Reporting the average response time, which hides the slow requests users complain about.
  • Running against an environment that is a fraction of production size and assuming results scale linearly.
