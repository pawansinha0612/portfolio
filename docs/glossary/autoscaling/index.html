What is Autoscaling?

Autoscaling automatically adds or removes servers, containers or pods based on measures such as CPU use, request rate or queue length, so capacity follows demand.

Why it matters

It saves money and handles gradual growth, but it is not instant. New capacity can take one to several minutes to start, pass health checks and warm up, and it can push the bottleneck down to the database.

An example

A Kubernetes deployment scales at 70% CPU. Traffic doubles in 30 s. The autoscaler checks metrics every 15 s, new pods take 60 s to pull the image and 45 s to warm up, so the existing pods run hot for about two minutes. By default, scaling down waits five minutes.

How to measure or test it

Load test with a realistic ramp and a spike, and time each step: when the trigger fired, when new instances were ready and when latency recovered. Check maximum instance counts and what they do to database connections.

Common mistakes

  • Relying on autoscaling for spikes that arrive faster than it can react.
  • Scaling on CPU for a service limited by I/O or a downstream service.
