    How it works

    Fake data that behaves like the real thing

    • Rows agree with each other. The email is built from the name on the same row. The postcode and state always match the suburb. A card's brand and CVV length match its number.
    • Orders add up. Each row is one order line. Quantity × unit price is the line total, and the order total is the sum of its lines. Order fields such as the date and status are the same on every line.
    • Seeded. A seed is any text. The same seed, columns and row count give exactly the same file, so a failed test can be run again with the same data.
    • Unique when you need it. IDs, emails and usernames never repeat. Any other column can be made unique. If it can't make enough values, for example ABC-## for 500 rows, you get an error that says so.
    • Fast. 100,000 rows take well under a second in a background worker, so the page doesn't freeze.

    Patterns

    The pattern type builds codes such as SKUs, references and booking numbers.

    • # is a digit, ? is a capital letter and * is a capital letter or digit.
    • [A-F] picks from a set. \d is a digit, and \ before any other character makes it literal.
    • {3} repeats the last item 3 times, and {2,4} repeats it 2 to 4 times.
    • Everything else is copied as is. ABC-#### gives ABC-0417. INV-[A-Z]{2}\d{5} gives INV-KQ20931.

    Using the file in a load test

    • k6. Load the file with open() inside a SharedArray, so 1,000 virtual users share one copy instead of holding 1,000. The snippet above picks one row per virtual user with exec.vu.idInTest.
    • JMeter. Leave Variable Names empty and the header row names the variables. Sharing mode All threads hands each thread the next unused row.
    • How many rows? For logins, at least one per virtual user. If every iteration needs a fresh row, rows must cover users × iterations. Otherwise rows get reused, and caches make the test look faster than real traffic.
    • Seeding a database. The SQL file uses multi-row INSERT statements of 500 rows each. Pick your database next to the table name. It changes how odd column names are quoted, how true and false are written and how backslashes are escaped. Create the table first.

    FAQ

    Is any of the generated data real?

    No. Names are common first and last names put together at random. Suburbs, states and postcodes are real combinations, but street numbers and names are made up. Emails use example.com, example.net and example.org, which are reserved for testing and can't receive mail. Mobile numbers are random 04 numbers, so some may belong to real people. Never send SMS to them.

    Are the card numbers safe to use?

    Yes. By default you get the public test card numbers that payment providers publish for their sandboxes. The other option makes numbers that pass the Luhn check on well-known test BINs. Both only work in test mode, and a sandbox such as Stripe's only accepts its own listed numbers.

    Can it make tax file numbers or Medicare numbers?

    Only fake ones that fail the official checksum on purpose. A number that passes could belong to a real person. The fake ones are useful for negative tests, to check your form rejects an invalid TFN or Medicare number.

    How do I give each virtual user its own row?

    In k6, load the file into a SharedArray and pick rows[(exec.vu.idInTest - 1) % rows.length]. In JMeter, use a CSV Data Set Config with Sharing mode set to All threads, Recycle on EOF set to False and Stop thread on EOF set to True.

    Will I get the same data next time?

    Yes. The same seed, columns and row count always give the same rows, so a failing test can be run again with exactly the same data. Change the seed for a fresh set.

    Is my data uploaded anywhere?

    No. The data is made in your browser and saved straight to your computer. Nothing is sent to a server.
