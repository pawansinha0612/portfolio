      How it works

      Every changed pixel, without the noise

      A plain pixel-by-pixel comparison fails on every run, because text edges render a little differently each time. This checker compares colours the way people see them and skips the soft edges.

      1. Pair. Screenshots are matched by folder and file name. Anything missing on either side is listed.
      2. Compare. Each pixel pair is compared in the YIQ colour space, which weights brightness the way the eye does. Differences under the colour tolerance are ignored.
      3. Skip anti-aliasing. A pixel that differs only because it sits on the soft edge of text or a shape is marked yellow and not counted.
      4. Decide. The share of changed pixels is checked against your threshold. Ignore areas (dates, ads, carousels) are left out of the count.

      Updating baselines

      When a change is intended, accept it as the new baseline. With Playwright, run npx playwright test --update-snapshots and commit the new images, or run the generated workflow by hand with “update baselines” ticked. Create baselines on the same operating system that compares them (the Linux CI runner, or the Playwright Docker image), because fonts render differently on macOS and Windows.

      Tips for stable screenshots

      • Mask anything that changes on every load: clocks, “last updated” dates, ads, random recommendations.
      • Hide cookie banners and chat widgets, or dismiss them before the screenshot.
      • Use fixed test data. A product list that changes order will fail every run.
      • Animations are stopped and the text cursor hidden by the generated config.
      • The generated config uses a colour tolerance of 0.1. Playwright's default of 0.2 can miss a colour change between two colours of similar brightness, such as a blue button turning green.

      FAQ

      Are my screenshots uploaded?

      No. Screenshots are decoded and compared in your browser tab. They never leave your computer, so it is safe for internal and unreleased pages.

      How are the screenshots paired?

      By folder and file name. home/desktop.png in the baseline is compared with home/desktop.png in the new set. Suffixes such as -expected, -actual, -baseline and -new are ignored, so Playwright and BackstopJS outputs pair up too.

      Why are some changed pixels shown in yellow?

      Yellow pixels are anti-aliasing: the soft edges of text and shapes that differ slightly between machines and browsers. They are not counted as changes unless you untick the anti-aliasing option. Red pixels are real changes.

      What change threshold should I use?

      Start with 0.1% of pixels and a colour tolerance of 0.1. Raise the threshold if fonts or shadows render slightly differently between runs; lower it for pixel-perfect components. Cover dates, ads and animations with ignore areas instead of raising the threshold.

      Can I run visual tests in CI for free?

      Yes. Playwright's toHaveScreenshot compares pages with committed baseline images, and GitHub Actions runs it free for public repositories and within the free minutes for private ones. The generator on this page writes the config, the test file and the workflow.
