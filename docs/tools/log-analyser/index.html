How it works

From thousands of lines to a short list of problems

  1. Format detection. The first 300 lines are tested against each format. Lines without a timestamp header (stack traces, wrapped messages) are joined to the entry above.
  2. Levels. Taken from the level field, a level word such as ERROR near the start of the line, a syslog priority, or an HTTP status (5xx is an error, 4xx a warning). Pino's numeric levels are understood.
  3. Error templates. Payment failed for order 12345 and Payment failed for order 12346 become one row: Payment failed for order <n>. The same is done for UUIDs, IPs, hex ids, emails, URLs, times and quoted strings.
  4. Exceptions. Java, Node.js, Python and Go stack traces are grouped by exception type and top frame, with the root cause from the last Caused by:.
  5. Timeline and spikes. Errors per minute (or a longer bucket for logs that span days). Spikes are buckets above the mean plus three standard deviations. Click a bar to see the errors in it.

Reading the results

Start with the first error, not the most common one. In an incident, the most frequent message is usually a symptom (every request failing because the database pool is empty). The first error in the spike is closer to the cause.

Times are shown as written in the log. If the log has a time zone offset, it is ignored, so the times match what you see in the file.

Tips for bigger logs

  • Choose the file rather than pasting it: the browser reads it in chunks and the page stays responsive.
  • For several files, join them first: cat app.log.* > all.log on macOS or Linux.
  • Compressed logs (.gz) need unzipping first: gunzip app.log.gz.

FAQ

Is my log uploaded anywhere?

No. The file is read and analysed in your browser, in a background thread. Logs often hold customer data, tokens and internal host names, so nothing is sent to a server.

Which log formats does it read?

JSON lines (pino, Bunyan, Winston, Serilog, Logstash, ECS), logfmt, timestamped application logs (Log4j, Logback, Spring Boot, Python logging, nginx error log), Apache and Nginx access logs in common or combined format, and syslog (RFC 3164 and 5424). Anything else is read as plain text, with levels found by keyword.

How does it group errors?

Each error message is turned into a template by replacing the parts that change between occurrences. Messages with the same template are counted together, with first seen, last seen and an example. Stack traces are grouped separately by exception type and top frame.

How is a spike detected?

A time bucket is a spike when its error count is more than the mean plus three standard deviations, and at least 3. The first error in each spike is shown because it is usually closest to the cause.

Where does the response time come from in an access log?

From a field such as rt=, request_time= or upstream_response_time=, or a number at the end of the line. A number with a decimal point is read as seconds (Nginx $request_time); a whole number is read as milliseconds.

How big a file can it handle?

50 MB and more. The file is read in 4 MB chunks in a Web Worker; a 50 MB log usually takes a few seconds. Up to 20,000 warning and error lines are kept for search.
