Tools · JMeter results

JMeter results analyser

Drop in a JMeter .jtl file and get the numbers your report needs: percentiles, error rate and throughput per transaction, charts over time, the top errors and a summary you can paste straight into a ticket.

🔒 Your file is never uploaded. It is read and analysed in your browser, on your machine. Results files often contain internal URLs, hostnames and error messages, so they never leave your computer.

Choose your results file

JMeter CSV (.jtl or .csv) or XML results. Large files are fine: a 2-million-row, 250 MB file is read in chunks without freezing the page. .jtl.gz works in current browsers.

How to get the file

Getting a results file out of JMeter

Run the test from the command line (non-GUI mode, the only way to run a real load test) and write results with -l:

jmeter -n -t plan.jmx -l results.jtl

Add -e -o report/ to also get JMeter's HTML dashboard. Its report/statistics.json works in the compare runs tool too.

Settings that make the analysis better

JMeter's defaults are fine. If your team changed them, check these in user.properties (or pass them with -J):

jmeter.save.saveservice.output_format=csv
jmeter.save.saveservice.print_field_names=true
jmeter.save.saveservice.timestamp_format=ms
jmeter.save.saveservice.thread_counts=true
jmeter.save.saveservice.bytes=true
jmeter.save.saveservice.sent_bytes=true
jmeter.save.saveservice.connect_time=true
jmeter.save.saveservice.latency=true
  • Column names matter, column order doesn't. Only elapsed is required. Without timeStamp you get no throughput or charts; without allThreads, no thread chart.
  • No header row? The file is read in JMeter's default column order.
  • XML results (output_format=xml) work. Only top-level samples are counted, so redirects and embedded resources aren't counted twice. CSV is smaller and much faster to write during a test, so prefer it.
  • Transaction Controllers appear as their own rows (marked TC) and are counted in TOTAL, as in JMeter's own reports.

Running k6 instead?

Paste k6's end-of-test output into the k6 results explainer. To compare two k6 runs, save each with k6 run --summary-export=run.json script.js and use compare runs.

What the numbers mean

Reading the summary

  • p50, p90, p95, p99: the response time that 50%, 90%, 95% or 99% of requests beat. p95 and p99 are what your slowest users feel; the average hides them. See percentiles and the interactive percentiles explainer.
  • Throughput: completed samples per second. See throughput. A drop in throughput while threads stay flat usually means the system slowed down, not that the load went down.
  • Error %: samples JMeter marked as failed, by response code or assertion.
  • How percentiles are calculated here: exactly, from every sample, using nearest-rank (the same rule as JMeter's Aggregate Report). JMeter's HTML dashboard interpolates between values, so on small samples its numbers can differ by a few milliseconds.
