How it works

A diff built for API testing

A text diff shows that line 214 changed. When you test an API you want to know which field changed, from what, to what. So this tool parses both documents and walks them together.

  1. Every difference has a JSON path, such as $.items[2].price. Keys that aren't plain names are quoted, such as $.headers["x-trace-id"].
  2. Four kinds of difference. Added (only in after), removed (only in before), changed (same type, new value) and type change. A type change such as number → string is listed on its own because it breaks clients that parse the field.
  3. Objects are compared by key, so key order never matters. Arrays are compared position by position, because order is part of the data for most APIs.
  4. The options remove noise. Volatile fields, reordered lists, rounding and null versus missing are the usual reasons two correct responses look different.

Writing ignore patterns

  • timestamp ignores every key called timestamp, at any depth.
  • *.id does the same for id. meta.requestId ignores requestId only inside an object called meta.
  • $.meta.requestId is an exact path from the root. $.items[*].id ignores id in every item.
  • created* ignores createdAt, createdBy and anything else starting with created.

Ignoring array order

With the box ticked, two arrays holding the same items in a different order are equal. Duplicates still count, so [1, 1, 2] and [1, 2, 2] differ. For arrays of objects, enter a key such as id. Objects with the same id are paired and compared field by field, so you see the field that changed rather than a whole object removed and another added.

From differences to assertions

Generate assertions writes one Playwright expect() line per difference, and a k6 check() block, using the after values. Paste them into a test that calls the same endpoint. That pins the new behaviour, so the next change gets caught.

const body = await response.json();
expect(body.status).toBe("SHIPPED");
expect(body.total).toBe("50.95");

When arrays are matched by key, the assertions find the item by that key instead of a position, such as body.items.find((x) => x.id === 2).price.

FAQ

Is my JSON uploaded anywhere?

No. Both documents are parsed and compared in your browser. API responses often hold customer data, tokens and internal hostnames, so nothing is sent to a server.

Does the order of keys in an object matter?

No. JSON objects have no order, so {"a":1,"b":2} and {"b":2,"a":1} are equal. Arrays do have an order, and they are compared position by position unless you tick Ignore array order.

How do I ignore ids, timestamps and trace ids?

List them in Ignore keys, separated by commas. A plain name such as timestamp matches that key at any depth. A pattern starting with $ is a full path. A * inside a name matches any characters.

How large a response can it compare?

Responses of 5 MB or more each. Large inputs are compared in a background thread so the page stays responsive. Integers above 9,007,199,254,740,991 lose precision when JavaScript reads them, so compare very large ids as strings.

Can I turn the differences into test assertions?

Yes. Generate assertions writes Playwright expect() lines and a k6 check() block for the differences in the table. Filter the table first if you only want some of them.
