      How it works

      Five steps, one page, no guesswork

      1. API and k6 script. Your OpenAPI or Swagger file becomes a k6 script, using the same converter as the OpenAPI to k6 tool. Perf Studio sizes it from your estimate and adds a threshold per endpoint, so k6 reports each endpoint on its own.
      2. Estimate. Little's Law turns peak users (or peak requests per hour), think time and response time into requests a second and VUs. You get the load per endpoint, and the five tests to run with their length. You also get the test data, the load generator size and the effort in days.
      3. Results. Load a k6 summary or a JMeter results file. You get throughput, p50 to p99 and errors per endpoint against your targets. Then come the bottleneck signals: latency rising with load, throughput flattening while users grow, errors bunched on one endpoint, and a long tail (p99 far above the median).
      4. Recommendations. Each signal maps to written rules: pools, autoscaling, indexes, caching, timeouts and retries, payload size. Every recommendation says which measured number triggered it.
      5. Report. A one-page go, go-with-risks or no-go verdict with the key numbers, top risks and next steps. Print it, or download it as HTML or Markdown.

      FAQ

      Does it use AI?

      No. Every number comes from your inputs or your results, and every rule is written down. The same results always give the same report, and you can see why each line is there.

      How is the verdict decided?

      No-go if anything blocking is found: overall p95 or error rate over the target, errors rising with load, a throughput plateau, timeouts or 5xx errors, or k6 running out of VUs. Go with risks if only warnings are found, such as one slow endpoint or a long tail. Go if neither.

      Why are some numbers in the estimate rules of thumb?

      Load generator size and effort depend on your scripts and team. The estimate lists every assumption it uses, so you can adjust it. Measured numbers in step 3 always come from your results.

      My JMeter file is huge.

      Files of a few hundred MB work, but big files are faster in the JMeter results analyser, which reads them in a background thread. Its percentiles are the same exact ones Perf Studio uses.
