Compare two load test runs

Baseline vs candidate: see which transactions got slower, which got faster and whether errors or throughput moved, against thresholds you set. Then paste the verdict into your PR or release ticket.

Regression thresholds

A transaction regresses when any metric gets worse by more than its threshold, and improves when one gets better by more than it. Leave a box empty to ignore that metric.

How to get the files

Saving each run so you can compare it

JMeter

Run in non-GUI mode and keep the results file from every run:

jmeter -n -t plan.jmx -l baseline.jtl
jmeter -n -t plan.jmx -l candidate.jtl -e -o report/

Either the raw .jtl files or each run's report/statistics.json work. The raw file gives exact percentiles; see the JMeter results analyser for the settings that matter in user.properties.

k6

k6 run --summary-export=baseline.json script.js
k6 run --summary-export=candidate.json script.js
  • Want p99? Add summaryTrendStats: ['avg', 'min', 'med', 'max', 'p(90)', 'p(95)', 'p(99)'] to options.
  • Want one row per request? Tag requests with { tags: { name: 'login' } } and add a threshold such as 'http_req_duration{name:login}': ['p(95)<500']. k6 only reports per-tag numbers for metrics with a threshold.
  • JSON from handleSummary(data) (write JSON.stringify(data)) works too, as does the text k6 prints at the end.

Make the comparison fair

  • Same script, same load profile, same test data and the same environment size. Otherwise you are comparing environments, not builds.
  • Run each side more than once if you can. Run-to-run noise of 5–10% on p95 is normal, which is why the default threshold is 10%.

What the numbers mean

Reading the comparison

  • p95 and p99 are the response times 95% and 99% of requests beat. They move before the average does, so they catch regressions first. See percentiles and the percentiles explainer.
  • Throughput is requests per second (more). With a fixed number of users, a slower system completes fewer requests, so a throughput drop next to a p95 rise is the same problem seen twice.
  • Error % is compared in percentage points: 0.5% → 1.6% is +1.1 points.
  • Few samples: with fewer than 30 samples a percentile is mostly noise. Don't fail a build on it.
