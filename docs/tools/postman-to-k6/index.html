How it works

What gets converted

  • Requests and folders. Every request runs in the order the Postman collection runner uses. Each folder becomes a k6 group(), so the end-of-test summary is broken down the same way. Disabled headers and query parameters are left out.
  • Variables. {{name}} stays in the script and is filled in when the request is sent, from a VARS object built from the collection and environment. Change any value at run time with -e name=value. Path variables like /users/:id and dynamic variables like {{$guid}}, {{$timestamp}} and {{$randomInt}} work too.
  • Auth. Bearer, Basic, API key (header or query) and a saved OAuth 2.0 token, inherited from the folder or collection like in Postman.
  • Bodies. Raw (JSON or text), x-www-form-urlencoded, form-data with files, GraphQL and binary files.
  • Tests. Common assertions become k6 checks: pm.response.to.have.status(200), pm.expect(pm.response.code).to.be.oneOf([…]), response time, headers, body text and simple JSON values such as pm.expect(jsonData.id).to.eql(42).
  • Chaining. pm.environment.set("token", pm.response.json().token) and the same for collection variables, globals and response headers become setVar(), so a token from the login request is sent with the next ones.

What you'll need to finish by hand

  • Pre-request scripts and complex tests (loops, schema validation, pm.sendRequest). They're kept as comments next to the request, and the warnings above the script list them.
  • Files for uploads. Put them next to the script. k6 reads them once at the start with open().
  • Test data. A collection that works for one person sends the same user, cart and order a thousand times under load. Give each virtual user its own data, for example from a CSV with SharedArray.

Run it

  1. Install k6 (brew install k6, winget install k6 or the Docker image grafana/k6).
  2. Start with a smoke test: k6 run --vus 1 --iterations 1 script.js, and check every check passes.
  3. Then run the real load with k6 run script.js, and paste the summary into the k6 results explainer.
  4. Ask before you load test a system you don't own. To a firewall, a load test looks like an attack.

FAQ

Can I run a Postman collection as a load test?

Postman's own runner sends requests one after another, so it suits functional checks, not real load. Converting the collection to a k6 script lets you run it with many virtual users or a fixed number of requests per second, with pass/fail thresholds on response time and errors.

Do my Postman tests carry over?

The common ones do: status codes, response time, headers, body text and simple JSON values become k6 checks. Anything more complex is kept as a comment for you to rewrite, and listed in the warnings.

Is the old postman-to-k6 command-line tool still an option?

The open-source postman-to-k6 tool from the k6 project is no longer maintained, and it depends on extra libraries at run time. This converter writes plain k6 JavaScript with no extra modules, apart from the official FormData helper for multipart uploads.

Is my collection uploaded anywhere?

No. The conversion runs in your browser. Your collection, environment, tokens and passwords never leave your computer.
