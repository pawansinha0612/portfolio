What gets converted

JMeter elements and their k6 equivalents

  • Thread Group → scenario (per-vu-iterations, ramping-vus or constant-vus)
  • Concurrency / Arrivals Thread Group → ramping-vus / ramping-arrival-rate
  • setUp / tearDown Thread Group → setup() / teardown()
  • HTTP Request + Defaults → http.get / post / put / del with BASE_URL
  • Header Manager → headers (with JMeter's scoping)
  • User Defined Variables, ${__P()} → vars and __ENV
  • CSV Data Set → SharedArray (one row per iteration)
  • Regex, JSON, Boundary, CSS extractors → variables
  • Response, Duration, Size, JSON assertions → check()
  • Timers → sleep()
  • Transaction Controller → group()
  • Loop, If, Once Only, Random, Interleave, ForEach, Throughput → JavaScript
  • Module Controller + Test Fragment → the fragment's steps, copied in
  • Groovy If conditions (vars.get, equals, getIteration) → JavaScript

What still needs you

  • Groovy and BeanShell scripts (JSR223 samplers and processors) can't be translated safely. Their code is copied into the script as a comment, marked TODO.
  • Non-HTTP samplers (JDBC, JMS, FTP, LDAP) have no k6 core equivalent. Some have xk6 extensions.
  • Listeners aren't needed: k6 prints a summary, and --out sends results to InfluxDB, Prometheus or a file.
  • Embedded resources ("retrieve all embedded resources") aren't fetched. Add the asset requests you care about, or test the page with k6's browser module.

After converting

  1. Search the script for TODO and read the notes above the script.
  2. Put any CSV files next to script.js. The script names each one.
  3. Smoke test first: k6 run --vus 1 --iterations 1 script.js, then compare the requests with a JMeter run.
  4. Read the result. Paste k6's end-of-test summary into the k6 results explainer.
