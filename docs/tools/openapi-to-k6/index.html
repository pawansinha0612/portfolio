How it works

From an API definition to a load test

  1. One request per endpoint. Each operation you tick becomes one k6 request, grouped by its first tag, so the results show times per area of the API (Books, Cart, Orders…). Every request is tagged with its path template, like /books/{bookId}, so thousands of different IDs still show as one line in the results.
  2. Example data. Values come from the example and examples in your definition first, then default and enum, and finally values made from the schema (a UUID for format: uuid, user@example.com for an email). $ref, allOf, oneOf and anyOf are followed, read-only fields are left out of request bodies, and circular references stop safely.
  3. Auth from environment variables. Bearer tokens, basic auth, API keys (header, query or cookie) and OAuth 2 become __ENV values, so no secret ends up in the script. Pass them with -e TOKEN=... when you run k6.
  4. Checks and thresholds. Each request checks for the success status the definition documents (201 for a create, 204 for a delete), and the test fails if p95 response time or the error rate goes over your limits.
  5. Run it. Install k6 (brew install k6, winget install k6 or the Docker image grafana/k6), then k6 run script.js. Paste the summary into the k6 results explainer for a plain-English verdict.

Before you point it at a real system

  • Replace example IDs. /pets/1 or a made-up UUID will often return 404. Use IDs that exist in your test environment, or read a list from a CSV with SharedArray.
  • Make it realistic. Real users don't call every endpoint once in order. Reorder and weight the requests to match your production traffic: most visitors search and browse, few check out.
  • Use test data. Requests that create orders or send emails will do it thousands of times. Agree on a test account and a clean-up plan first.
  • Ask before you load test a system you don't own, and start small: 1 VU for 30 seconds as a smoke test, then build up.

FAQ

Can I convert a Swagger 2.0 file?

Yes. Swagger 2.0 and OpenAPI 3.0 and 3.1 all work, in JSON or YAML. For Swagger 1.x, convert the file to 2.0 or 3.0 first.

My definition is split across several files.

References to other files can't be followed in the browser. Bundle it into one file first, for example with npx @redocly/cli bundle openapi.yaml -o bundled.yaml, then upload that.

Is a script generated from OpenAPI a realistic load test?

It's a good start for checking every endpoint under load and catching the slow ones. A realistic test follows the journeys real users take, in the proportions they take them. If you have browser traffic, the curl to k6 converter turns a recorded journey into a script.
