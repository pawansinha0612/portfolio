How to use it

Before you run it: an LLM load test costs real money

  1. Use a separate API key or project with its own spending cap. Rate limits are usually per key or per organisation, so a test on the production key can throttle real users.
  2. Check your provider's rate limits and terms. Note your requests-per-minute and tokens-per-minute limits first. For a big test, tell the provider or your account manager.
  3. Smoke test first: k6 run --vus 1 --iterations 3 -e LLM_API_KEY=… llm-test.js. Check the answers aren't empty and the token counts look right.
  4. Then run the real test and watch the 429 rate and cost lines at the end.

What the script measures

MetricWhat it tells you
llm_ttftTime to first token: how long users stare at a blank chat bubble. An approximation: k6 can't read a response while it streams, so this is the time to the first byte. Providers usually send the first byte with the first token, so it's close, but a gateway that sends headers early will make it look better than it is. Only measured with streaming on.
llm_latencyFull answer time for successful requests.
llm_output_tokens_per_sGeneration speed once the answer starts (with streaming), or end to end (without). It drops when a provider or your own GPU server is busy.
llm_rate_limitedShare of attempts answered with 429. The first sign you've hit requests-per-minute or tokens-per-minute limits.
llm_errorsRequests that still failed after retries, plus empty answers.
llm_input_tokens / llm_output_tokensRead from the response's usage block. If the API doesn't return one, the script estimates at 4 characters a token and says so.

Reading the result

  • 429s with low tokens per second: you hit the provider's limit. Ask for a higher tier, spread load over several deployments or regions, or cut max_tokens. Many providers count max_tokens against your limit, even when the answer is shorter.
  • TTFT climbs with load but tokens per second holds: requests are queuing before the model starts. Typical of self-hosted vLLM or Ollama with too few GPUs, or a gateway with too few connections.
  • Tokens per second falls as load rises: the model server is saturated. Batch size, GPU memory and KV cache are the usual suspects.
  • Retries make things worse: if your app retries instantly, a 429 becomes three requests. Compare runs with retries on and off.
