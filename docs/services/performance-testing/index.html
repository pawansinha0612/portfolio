Gaming & Lottery

The Lottery Corporation

2025 to present

An AI-powered performance testing framework, adopted company-wide

Challenge: Powerball, Oz Lotto and Keno see massive traffic spikes on draw nights, and hand-scripting load tests couldn't keep up with how often the team released.

What I did: Built a k6 framework that generates typed API clients from OpenAPI specs, uses GitLab Duo to turn plain-English scenarios into ready-to-run tests, and runs in GitLab CI on every deployment. Added live Grafana/InfluxDB and Kibana dashboards, and used Dynatrace to trace slow Oracle queries, memory leaks and GC pressure.

Outcome: Writing test scripts now takes minutes instead of days, every deployment passes a performance gate, and the framework became the standard approach across engineering squads.

Questions

Common questions

Can you test against production?

Usually not, and you rarely need to. I test a production-like environment and scale the results, and I'll tell you plainly where the environment differs and what that means for the numbers.

Which tool will you use?

The one that fits your team. k6 is my default for new work because it lives in your repo and your pipeline. If you already have JMeter or LoadRunner scripts, I'll build on them.

How long does a load test take?

A focused go-live test is usually one to two weeks: a few days to model and script, then runs, diagnosis and the report.

Do you only find problems or also help fix them?

Both. I trace slowdowns to the query, endpoint or setting behind them and work with your developers on the fix, then re-test.
