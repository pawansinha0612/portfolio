How to read a load test like this

  • Find the first thing that flattens. Throughput stops rising when something is full. Look for the resource that hit its limit at the same moment.
  • Busy versus waiting. High CPU means work is queueing for compute. Low CPU with high latency means requests are waiting on something: a pool, a lock, the disk or another service.
  • Averages hide hot spots. Check per instance, per shard and per core before you call it healthy.
  • Steady load, changing behaviour points to time: leaks, growing tables, expiring caches.

That's the USE method in practice. The long version: bottleneck analysis is a method, not a guess.
