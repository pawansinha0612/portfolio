VUs or requests per second?

      
Load, stress and soak tests here use virtual users (ramping-vus): each one loops through the journey with think time, like a person. Spike and breakpoint tests use arrival rate (ramping-arrival-rate): k6 starts requests on schedule whether or not the server keeps up, which is how real traffic behaves when it surges. If the system slows down, a VU test quietly sends less traffic; an arrival-rate test doesn't. More in the glossary: open vs closed workload models and arrival rate.

      
Common mistakes

      
    
        
  • No ramp-up. Jumping straight to full load tests your cold caches and connection setup, not your steady state. See ramp-up.
    • 
        
  • Steady state too short. Five minutes at peak won't show a slow leak. That's what the soak test is for.
    • 
        
  • Breakpoint tests on production. The point is to break something. Use a test environment that's sized like production.
    • 
        
  • Too few VUs for the arrival rate. k6 warns about "insufficient VUs". By Little's law, VUs needed ≈ requests per second × response time in seconds.
