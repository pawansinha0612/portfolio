Peak-readiness checklist

23 checks to run before Black Friday, Click Frenzy, Christmas or any big launch.

Get it done for you

Traffic and targets

  • Peak hour forecast from last year's analytics plus this year's campaign plans
  • Response time targets agreed for home, search, product, cart and checkout
  • Error rate target agreed (for example under 1% at peak)
  • Marketing send times known, so you can plan for the email-blast spike

Testing

  • Load test of the key shopper journeys at forecast peak
  • Spike test: traffic jumps from normal to peak within a minute
  • Soak test at peak for 1–2 hours to catch leaks and slow build-up
  • Breaking point found, so you know your real headroom
  • Retest after every fix, on the release that will go live

Infrastructure

  • Autoscaling limits, warm-up time and cloud account quotas checked
  • Database connections, slow queries and indexes reviewed under load
  • CDN caching rules confirmed for images, scripts and product pages
  • Rate limits and bot protection tested, so they don't block real shoppers

Third parties

  • Payment gateway, fraud check and tax services told your expected volume
  • Search, reviews, chat and tag scripts load without blocking checkout
  • A fallback plan if a third party slows down (timeouts, feature switches)

Release and monitoring

  • Code and config freeze dates agreed before peak week
  • Dashboards for traffic, response time, errors and orders per minute
  • Alerts set on the numbers that matter, sent to people who will act
  • Rollback plan tested, not just written

On the day

  • Named people on call, with a shared chat channel
  • Holding page and queue plan ready if traffic beats the forecast
  • A quick review the week after, while it's fresh, for next year
