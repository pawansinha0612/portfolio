Locust load shapes: any profile, in code

"Ramp to 100 users and hold" answers one question. The questions that matter are harder: what happens when traffic doubles in a minute, and does the system recover afterwards? A LoadTestShape lets you script that profile in a few lines of Python.

On this page

  1. How a shape works
  2. Steps, a spike and recovery
  3. Different users at different times
  4. Gotchas

How a shape works

Add a subclass of LoadTestShape to your locustfile. Locust calls its tick() method about once a second. tick() returns a tuple of (user_count, spawn_rate), optionally with a list of user classes as a third item, or None to stop the test. self.get_run_time() gives the seconds since the test started.

The shape sets how many users exist, not how many requests they send. The request rate still comes from the users' wait_time and the response times. For a rate-based profile, combine a shape with constant_throughput or constant_pacing (see wait_time).

Steps, a spike and recovery

from locust import HttpUser, LoadTestShape, task, constant


class ApiUser(HttpUser):
    wait_time = constant(1)

    @task
    def browse(self):
        self.client.get("/products")


class StepThenSpike(LoadTestShape):
    """Steps of 50 users every 2 minutes up to 200, a 1-minute spike to 500, then stop.

    tick() is called about once a second. Return (user_count, spawn_rate),
    optionally with a list of user classes, or None to stop the test.
    """

    stages = [
        # (end time in seconds, users, spawn rate per second)
        (120, 50, 10),
        (240, 100, 10),
        (360, 150, 10),
        (480, 200, 10),
        (540, 500, 50),   # spike
        (660, 200, 50),   # recovery: does latency come back down?
    ]

    def tick(self):
        run_time = self.get_run_time()
        for end, users, rate in self.stages:
            if run_time < end:
                return users, rate
        return None
locust -f shape.py -H https://staging.example.com --headless --csv results/step

Read the result per stage, not as one number:

  • Each step: did p95 settle at a new level, or keep climbing during the step? A climb within a step means work arrives faster than it's done: a queue is growing. See queueing.
  • The spike: errors, timeouts and autoscaling lag. See spike testing.
  • Recovery: back at 200 users, does latency return to the level it had at 200 users on the way up? If not, something stayed broken: a full queue, exhausted connection pool, or a retry storm. That's the most valuable finding in this test, and the one a plain ramp never shows.

The _stats_history.csv file from --csv has a row every few seconds, so you can chart each stage. The HTML report (--html) has the same charts.

Different users at different times

The optional third item picks which user classes to spawn. Class weight sets the mix between them:

from locust import HttpUser, LoadTestShape, task, constant


class Browser(HttpUser):
    weight = 9
    wait_time = constant(2)

    @task
    def browse(self):
        self.client.get("/products")


class Buyer(HttpUser):
    weight = 1
    wait_time = constant(5)

    @task
    def buy(self):
        self.client.get("/products/3", name="/products/[id]")


class MorningRush(LoadTestShape):
    """Background browsing all the time, plus buyers only during the 'sale'."""

    def tick(self):
        t = self.get_run_time()
        if t < 300:
            return 50, 5, [Browser]              # 5 min of browsing only
        if t < 900:
            return 150, 10, [Browser, Buyer]     # 10 min sale: both classes, by weight
        if t < 1200:
            return 50, 10, [Browser]             # back to browsing
        return None

At 150 users with weights 9 and 1, you get about 135 browsers and 15 buyers.

Gotchas

  • -u, -r and -t are ignored when the locustfile has a shape class, and Locust logs a warning. The shape decides. A shape that never returns None runs forever, so make sure the last stage ends.
  • A spawn rate is a speed, not a step. Going from 200 to 500 users at 50 a second takes 6 seconds. For a sharper spike, raise the spawn rate. Very high spawn rates cost CPU on the load generator.
  • Removing users stops them mid-task. Locust stops surplus users immediately by default. Set --stop-timeout to let them finish the current task first.
  • Distributed runs: the shape runs on the master, and the master spreads the users across workers. Nothing changes in the shape code.
