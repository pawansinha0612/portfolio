Locust data and auth: real users, real sessions

The Locust report shows zero failures. The API returned 200 {"error": "session expired"} to most requests, and Locust counted every one as a success. Here's how to log users in properly, give them their own data, and fail the responses that are wrong.

  1. Log in once per user with on_start

Log in once per user with on_start

on_start runs once when each simulated user starts, before its first task. on_stop runs when the user stops. Each user has its own self.client with its own cookies and default headers, so a token set there belongs to that user only.

import csv
import itertools
import os

from locust import HttpUser, task, between
from locust.exception import StopUser

# Load accounts once per process. itertools.cycle hands each new user the next row.
with open(os.path.join(os.path.dirname(__file__), "users.csv"), newline="") as f:
    USERS = list(csv.DictReader(f))
user_rows = itertools.cycle(USERS)


class LoggedInUser(HttpUser):
    wait_time = between(1, 2)

    def on_start(self):
        # Runs once when each simulated user starts, before its first task
        creds = next(user_rows)
        token = None
        with self.client.post("/login", json=creds, catch_response=True) as res:
            if res.status_code == 200 and "access_token" in res.text:
                token = res.json()["access_token"]
            else:
                res.failure(f"login failed: {res.status_code}")
        if token is None:
            raise StopUser()  # don't let a user with no session hammer the API with 401s
        # Every later request from this user carries the token
        self.client.headers.update({"Authorization": f"Bearer {token}"})

    @task
    def add_to_cart(self):
        cart_id = None
        with self.client.post("/cart", json={"productId": 7}, catch_response=True) as res:
            # Locust only fails 4xx/5xx by default. Check the body too.
            if res.status_code != 201:
                res.failure(f"unexpected status {res.status_code}")
            elif not res.json().get("cartId"):
                res.failure("no cartId in response")
            else:
                cart_id = res.json()["cartId"]
        if cart_id:
            # Correlation: reuse the value from the previous response
            self.client.post("/orders", json={"cartId": cart_id})
  • The CSV is read once per process at import time and shared by all users in that process. itertools.cycle gives each new user the next account.
  • self.client.headers.update(...) adds the token to every later request from this user. For cookie-based sessions you don't need even that: the client keeps cookies per user.
  • raise StopUser() stops a user whose login failed. Otherwise it would spend the whole test sending requests that return 401, and those failures would bury the real ones.

catch_response: decide what a failure is

By default Locust counts a request as failed only on a connection error or a status of 400 or above. With catch_response=True the request becomes a context manager and you decide:

with self.client.get("/search?q=shoes", catch_response=True) as res:
    if res.status_code != 200:
        res.failure(f"status {res.status_code}")
    elif "results" not in res.text:
        res.failure("no results key")       # 200, but wrong
    elif res.elapsed.total_seconds() > 2:
        res.failure("slower than 2 s")      # count slow responses as failures (optional)
    # otherwise it's a success; res.success() also turns an expected 404 into a success

Only call failure() or success() inside the with block, and only on responses requested with catch_response=True. A plain response object doesn't have them.

An ordered journey with correlation

Tasks on a user are picked at random by weight. For a journey that must happen in order (list, add to cart, pay), use a SequentialTaskSet. Values extracted in one task go on self and are read by the next:

import re
import uuid

from locust import HttpUser, SequentialTaskSet, task, between


class Checkout(SequentialTaskSet):
    """Tasks run in the order written, then start again from the top."""

    @task
    def list_products(self):
        res = self.client.get("/products")
        items = res.json().get("items", []) if res.ok else []
        self.product_id = items[0]["id"] if items else 1

    @task
    def add_to_cart(self):
        with self.client.post(
            "/cart",
            json={"productId": self.product_id, "ref": f"load-{uuid.uuid4()}"},
            catch_response=True,
        ) as res:
            if res.status_code == 201 and "cartId" in res.text:
                self.cart_id = res.json()["cartId"]
            else:
                self.cart_id = None
                res.failure(f"add to cart: {res.status_code}")

    @task
    def pay(self):
        if not self.cart_id:
            self.interrupt(reschedule=True)  # abandon this journey, start a new one
        with self.client.get("/checkout", catch_response=True) as page:
            match = re.search(r'name="csrf" value="([^"]+)"', page.text)
            if not match:
                page.failure("no CSRF token on checkout page")
        if not match:
            self.interrupt(reschedule=True)
        self.client.post("/checkout", data={"csrf": match.group(1), "cartId": self.cart_id})


class Shopper(HttpUser):
    wait_time = between(1, 3)
    tasks = [Checkout]

    def on_start(self):
        res = self.client.post("/login", json={"username": "user001", "password": "Passw0rd!"})
        self.client.headers["Authorization"] = f"Bearer {res.json()['access_token']}"

    def on_stop(self):
        # Runs when the user is stopped: log out or clean up if the system needs it
        pass
  • JSON: res.json() and plain Python.
  • HTML: a regex for one hidden field, as above. For more, parse with a library you already use, but keep it light: parsing costs CPU on the load generator.
  • self.interrupt(reschedule=True) abandons the rest of this journey and starts the next one, so a broken step doesn't cascade into failures in every later step.
  • Unique values, like the order reference here, keep writes from colliding when many users create records at once.

Test data: one account per user

  • Enough rows for the peak. 500 users cycling through 50 accounts means ten users per account. Sessions can kick each other out, and per-user rate limits trip. Make sure the account count is at least the peak user count.
  • Distributed runs: each worker loads its own copy of the file. Split it by worker index so workers don't share accounts. See splitting data between workers.
  • Read-only data (search terms, product ids) can be random: random.choice(ROWS).
  • Secrets go in environment variables (os.environ), never in the locustfile or the CSV committed to git.

Tips

  • Name dynamic URLs. name="/orders/[id]" on every request with an id in the path.
  • Debug with one user in the web UI, with logging, before adding load. Locust also has a run_single_user helper for stepping through a user in a debugger.
  • Don't login every task. Unless you're testing the login service, it overloads auth and hides the latency of the calls you care about.
