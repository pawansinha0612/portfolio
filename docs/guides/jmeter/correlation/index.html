JMeter correlation: stop replaying yesterday's token

Your recorded script passes with one user and fails with ten. Every login returns 200, every "add to basket" returns 403, and the response body says "invalid CSRF token". The script is replaying a value the server issued once, during recording. Correlation fixes that: capture the value from a response, then send it back on the next request.

1. Find what needs correlating

Correlation means any value the server generates that the client must send back: session IDs, CSRF or anti-forgery tokens, OAuth state and code, order and basket IDs, pagination cursors, ASP.NET __VIEWSTATE, signed URLs. The reliable way to find them:

  1. Record the same flow twice (two logins, two orders).
  2. Diff the two recordings. Any request parameter, header or path segment that differs is either dynamic data from the server (correlate it) or data you chose (parameterise it).
  3. For each dynamic value, search the earlier responses for where it first appears. That response is where the extractor goes.

Cookies are the exception. The HTTP Cookie Manager handles Set-Cookie automatically, so do not extract session cookies by hand unless the app copies them into a header or body.

2. Which extractor to use

All extractors are Post Processors: right-click the sampler whose response contains the value, then Add → Post Processors. Put the extractor as a child of that one sampler. Placed higher up, it runs after every sampler in scope and can overwrite a good value with the default.

Response is…UseWhy
JSONJSON ExtractorReadable JSONPath, survives field reordering and whitespace changes
HTML, value between fixed textBoundary ExtractorNo regex escaping, and the cheapest on CPU
Anything needing a pattern (headers, mixed text)Regular Expression ExtractorMost flexible, several groups at once
HTML where structure mattersCSS Selector ExtractorSelects by element and attribute, e.g. input[name=csrf]
XML or SOAPXPath2 ExtractorProper XML parsing with namespaces

3. JSON Extractor

Say the login call returns:

{"user":{"id":4182,"name":"Ana"},"accessToken":"eyJhbGciOi...","basket":{"id":"b-77a1","items":[]}}

Add Post Processors → JSON Extractor under the login request:

FieldValue
Names of created variablestoken;basketId
JSON Path expressions$.accessToken;$.basket.id
Match No. (0 for Random)1;1
Default ValuesTOKEN_NOT_FOUND;BASKET_NOT_FOUND

Lists are semicolon-separated and must have the same number of entries in every field. Useful JSONPath forms:

$.items[0].sku                         first item's sku
$.items[*].sku                         every sku (pair with Match No. -1)
$.items[?(@.stock > 0)].sku            skus that are in stock
$..orderId                             orderId at any depth (slower on big bodies)

4. Regular Expression Extractor

For a hidden form field like <input type="hidden" name="csrf" value="9f2c1e...">:

FieldValue
Apply toMain sample only
Field to checkBody (use Response Headers for a header value)
Name of created variablecsrf
Regular Expressionname="csrf" value="([^"]+)"
Template$1$
Match No. (0 for Random)1
Default ValueCSRF_NOT_FOUND
  • The regex needs a capture group (...). The template picks groups: $1$ is the first, $1$-$2$ joins two.
  • Prefer ([^"]+) over (.+?). A negated character class cannot run past the closing quote, and it backtracks less.
  • Do not wrap the expression in / /. Add (?s) at the start if the value can span lines, and (?i) to ignore case.
  • Each group is also stored as csrf_g1, csrf_g2 and so on, with csrf_g0 holding the whole match.
  • For a redirect location or header token, set Field to check to Response Headers and use something like Location: .*[?&]code=([^&\s]+).

5. Boundary Extractor

When the value sits between two fixed strings, the Boundary Extractor (added in JMeter 4.0) is simpler and cheaper than a regex because it does plain string searches:

FieldValue
Name of created variablecsrf
Left Boundaryname="csrf" value="
Right Boundary"
Match No. (0 for Random)1
Default ValueCSRF_NOT_FOUND

Boundaries are literal text, so there is nothing to escape. Make the left boundary specific enough to be unique, or you will capture the first match on the page instead of the one you meant.

6. Using the value: ${var}

Reference the variable anywhere later in the same thread: a parameter, a path, a body or a header.

Path:            /api/baskets/${basketId}/items
Body Data:       {"sku":"${sku}","qty":1}
Parameter:       csrf = ${csrf}
Header Manager:  Authorization = Bearer ${token}

Two rules that explain most "it doesn't work" moments:

  • Variables are per thread. Thread 7's ${token} is thread 7's own. To share a value across threads or thread groups you need a property, covered in auth tokens.
  • An unknown variable is sent literally. JMeter does not raise an error for an undefined ${csrf}. It sends the text ${csrf} to the server. That is why a distinctive default value matters: CSRF_NOT_FOUND in a request log tells you instantly which extractor failed.

If a value is URL-encoded in one place and raw in another, convert it with ${__urlencode(${csrf})} or ${__urldecode(${csrf})}. HTML entities such as &amp; can be decoded with ${__unescapeHtml(${value})}.

7. Match numbers and "extract all"

Match No.Result
1, 2, …The nth match, stored in var
0A random match. Good for "pick any product from the list"
-1All matches: var_1 … var_N, plus var_matchNr with the count

With -1, loop over the results with a ForEach Controller (input variable prefix var, output variable name item, "Add "_" before number" ticked). The JSON Extractor can also join every match into var_ALL when "Compute concatenation var" is ticked.

Random choice (0) is realistic but makes runs less repeatable. If an intermittent error only happens for some products, you will want to know which product it was. Log the chosen value in the sampler name or a response assertion message while you investigate.

8. Debugging extractors

  1. Test the expression on a real response. In View Results Tree, select the sample, then change the renderer dropdown (bottom left, "Text" by default) to RegExp Tester, JSON Path Tester, Boundary Extractor Tester or CSS Selector Tester. Type the expression and press Test.
  2. See what was actually stored. Add Sampler → Debug Sampler right after the request, with JMeter variables set to true. Its response, shown in View Results Tree, lists every variable in that thread.
  3. Check the next request, not just the extractor. In View Results Tree, open the following sample's Request tab and confirm the real value went out, correctly encoded.
  4. Check scope. An extractor at Thread Group level runs after every sampler, including ones whose response does not contain the value, and resets the variable to its default.
  5. Check the right response. If the value arrives after a redirect, it is in the final sample, or in a sub-sample if "Follow Redirects" is on. Set "Apply to" accordingly.

Remove or disable Debug Samplers before load runs. They add samples to your results and skew throughput.
