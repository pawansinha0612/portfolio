k6 with TypeScript, and a structure that survives a team

The first load test was one 80-line file. Six months later there are 14 copies of it, each with its own login function, and an API change means editing all of them. Structure is what keeps a load test suite cheap to maintain.

TypeScript in k6: no build step

Since k6 v0.57, k6 run script.ts works with no flag and no bundler. k6 uses esbuild internally to strip the types and run the JavaScript. Two things to know:

  • k6 does not type-check. It removes the types and runs. A type error that tsc would reject runs fine in k6, until it fails at runtime. Run tsc yourself (below).
  • Imports use the real file name, including .ts. k6 doesn't do Node-style module resolution, so import { login } from '../lib/api.ts', not '../lib/api'.

On older versions (v0.52 to v0.56), TypeScript needed --compatibility-mode=experimental_enhanced. Before that, people bundled with webpack or esbuild. If you see those in an old repo, you can remove them after upgrading.

A project layout

perf/
├── config/
│   └── env.ts          # base URLs and budgets per environment
├── lib/
│   └── api.ts          # one function per endpoint: request, tag, checks
├── data/
│   └── users.csv       # test data (generated, never real customers)
├── tests/
│   ├── smoke.ts        # 1-5 VUs, every pull request
│   ├── shop.ts         # the main journey under load
│   └── soak.ts         # same journey, hours long
├── package.json        # only for @types/k6 and tsc, nothing k6 needs at runtime
└── tsconfig.json

The split that matters: tests describe load and journeys, lib describes how to call the API. When an endpoint changes, you change one function in lib/ and every test picks it up.

The code

config/env.ts picks settings from TARGET_ENV:

// config/env.ts: one place for environment-specific settings
export interface EnvConfig {
  baseUrl: string;
  p95Ms: number;
}

const envs: Record<string, EnvConfig> = {
  local: { baseUrl: 'http://localhost:8080', p95Ms: 800 },
  staging: { baseUrl: 'https://staging.example.com', p95Ms: 500 },
};

export const env: EnvConfig = envs[__ENV.TARGET_ENV || 'local'];
if (!env) throw new Error(`unknown TARGET_ENV: ${__ENV.TARGET_ENV}`);

lib/api.ts wraps each endpoint with its name tag and its checks, so no test can forget them:

// lib/api.ts: one function per endpoint, with the tag and the checks built in
import http, { RefinedResponse, ResponseType } from 'k6/http';
import { check } from 'k6';
import { env } from '../config/env.ts';

export interface Product {
  id: number;
  name: string;
  price: number;
}

const json = { 'Content-Type': 'application/json' };

export function login(username: string, password: string): string {
  const res = http.post(`${env.baseUrl}/login`, JSON.stringify({ username, password }), {
    headers: json,
    tags: { name: 'POST /login' },
  });
  check(res, { 'login 200': (r) => r.status === 200 });
  return res.json('access_token') as string;
}

export function listProducts(): Product[] {
  const res: RefinedResponse<ResponseType> = http.get(`${env.baseUrl}/products`, {
    tags: { name: 'GET /products' },
  });
  check(res, { 'products 200': (r) => r.status === 200 });
  return (res.json('items') as unknown as Product[]) || [];
}

export function addToCart(token: string, productId: number): void {
  const res = http.post(`${env.baseUrl}/cart`, JSON.stringify({ productId }), {
    headers: { ...json, Authorization: `Bearer ${token}` },
    tags: { name: 'POST /cart' },
  });
  check(res, { 'cart 201': (r) => r.status === 201 });
}

tests/shop.ts is just the journey and the load:

// tests/shop.ts: the test only describes the journey and the load
import { sleep } from 'k6';
import { Options } from 'k6/options';
import { env } from '../config/env.ts';
import { login, listProducts, addToCart } from '../lib/api.ts';

export const options: Options = {
  vus: 10,
  duration: '5m',
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: [`p(95)<${env.p95Ms}`],
  },
};

export default function (): void {
  const token = login('user001', 'Passw0rd!');
  const products = listProducts();
  sleep(1);
  if (products.length > 0) addToCart(token, products[0].id);
  sleep(1);
}
k6 run tests/shop.ts                           # local
k6 run -e TARGET_ENV=staging tests/shop.ts     # staging budgets and URL

Type-checking in CI

Install the type definitions and TypeScript as dev dependencies. k6 never reads node_modules, they're only for your editor and tsc.

npm install --save-dev typescript @types/k6
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "noEmit": true,
    "strict": true,
    "types": ["k6"]
  },
  "include": ["config", "lib", "tests"]
}

allowImportingTsExtensions (which needs noEmit) lets tsc accept the .ts imports that k6 requires. Then run npx tsc -p . in CI before any load test, and run k6 inspect on each test to catch k6-level errors (bad options, missing files) without sending any traffic.

npx tsc -p .                 # types
k6 inspect tests/shop.ts     # k6 can load the script and its options
k6 run --vus 1 --iterations 1 tests/shop.ts   # one real pass

Keep @types/k6 close to your k6 version. The types follow the k6 API, so a mismatch flags functions you don't have, or misses ones you do.

Rules that keep it maintainable

  • No URLs, budgets or credentials in test files. URLs and budgets live in config, credentials come from __ENV.
  • Every request has a name tag. Put it in the lib function so it's never forgotten.
  • Checks live with the call. The lib function knows what a good response looks like.
  • Load shape lives in the test. The same journey is reused by smoke, load and soak tests with different options.
  • No npm packages at runtime. k6 can import local files and remote URLs (such as jslib), not packages from node_modules. If you need an npm library, bundle it into a single file first, and check it doesn't use Node APIs that k6 doesn't have.
