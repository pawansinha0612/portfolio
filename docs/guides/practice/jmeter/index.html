Exercise 10: the same test in JMeter

Your new client runs JMeter, and your scripts are in k6. Or the other way round. The concepts carry over exactly: virtual users, think time, assertions, correlation, percentiles. The vocabulary and the defaults don't, and the defaults are where two tools quietly disagree about the same server.

  • Optional
  • 30 minutes
  • 5 threads, 1 minute
  • Run locally only

Goal

Run the pizza journey from Exercise 5 as a JMeter test plan, from the command line, with a response assertion and a JSON extractor. Then compare JMeter's numbers with k6's for the same load on the same server.

Setup

Install Java 17 or later and JMeter 5.6 (brew install jmeter on macOS, or see getting started with JMeter). Start QuickPizza:

docker run --rm --name quickpizza -p 3333:3333 ghcr.io/grafana/quickpizza-local:latest

The test plan

Save as pizza.jmx. Open it in the JMeter GUI first (jmeter -t pizza.jmx) to see the tree, but don't run load from the GUI.

HTTP Header Managerheaders in the request params

Run it

jmeter -n -t pizza.jmx -l pizza.jtl -e -o report

Then run k6 at the same load, using the script from Exercise 2 with its users and duration overridden on the command line:

k6 run --vus 5 --duration 60s --summary-export=k6-pizza.json 02-thresholds.js

Open report/index.html for JMeter's dashboard. Then load pizza.jtl and k6-pizza.json into the compare runs tool. Both tools name the request pizza, so they line up on one row.

What you should see

JMeter prints a summary line every 30 seconds and a final one, something like this (illustrative):

summary =    263 in 00:01:00 =    4.4/s Avg:    62 Min:    10 Max:   190 Err:     0 (0.00%)

The count includes both pizza and rate samples. In the HTML report, the Statistics table has one row per label with percentiles. pizza's p95 should be in the same range as k6's. Don't expect identical numbers.

Questions

  1. Stop QuickPizza, start a fresh one, and edit the plan so the Authorization header says token wrongtoken000000. Run it. What does JMeter report, and how is that different from Exercise 1's k6 run with a bad token and no thresholds?
  2. The JSON Extractor has a default value of NOT_FOUND. What happens to the rate request when the pizza request fails? What if you change the Thread Group's error action to Continue?
  3. JMeter's Thread Group is a closed model. What would you use in JMeter for an open model like Exercise 4's arrival rate?
  4. Paste pizza.jmx into the JMeter to k6 converter. What did it translate cleanly, and what would you still fix by hand?
Answer / what to look for
  1. Every pizza sample is an error (Err: 100%) because the 401 fails the response assertion, and no rating requests are sent at all, because the Thread Group starts the next loop after a failed sampler. But jmeter -n still exits with code 0 when samples fail. Like k6 without thresholds, it needs a pass/fail step, for example a CI step that reads the JTL or statistics.json and fails on error rate or p95.
  2. In this plan, nothing: the Thread Group's "Action to be taken after a Sampler error" is Start Next Thread Loop, so the rating is skipped. Set it to Continue and the rating request is sent with {"pizza_id": NOT_FOUND, "stars": 5}, which is invalid JSON, and fails with an error of its own. That second error is noise caused by the first, and it doubles your error count. For finer control, wrap the rating in an If Controller that checks "${pizzaId}" != "NOT_FOUND". In k6, the return after a failed check does the same job.
  3. The Open Model Thread Group (built in since JMeter 5.5) or the Arrivals and Concurrency thread groups from the plugins. A Constant Throughput Timer only caps throughput: it can't start more threads when the server slows down. See thread groups and load shapes.
  4. The request, headers, think time and extractor usually translate well. Expect to review the assertion (a k6 check doesn't fail the request the way a JMeter assertion does, so add thresholds), the property-based host and port, and anything that relies on JMeter scoping rules. Treat converter output as a first draft, not a finished script.
