How to use it

  • Use the busiest real hour, not a daily total divided by 24. Traffic is never flat.
  • Prefer an arrival-rate (open) model for public traffic. You set iterations per second and the tool adds users. Load profiles explained shows why it matters.
  • Check your sums online: the workload model tool does the same calculation in the browser.
  • New to the maths? Little's Law and pacing in the glossary explain the two formulas that matter.

2. Formulas

  • Target per hour = peak hour (production) × uplift
  • Iterations per second = target per hour ÷ 3,600
  • Iteration time = the sum of response times and think times for one pass through the journey script
  • Minimum VUs (Little's Law) = iterations per second × iteration time
  • VUs with spare = minimum VUs × 1.25, rounded up, so slower responses under load don't cut throughput
  • Pacing = VUs with spare ÷ iterations per second. Each virtual user starts a new iteration this often.

With an open-model tool setting (k6 constant-arrival-rate, Gatling injectOpen, JMeter's Open Model Thread Group) you set iterations per second directly and the tool adds users as needed. Use the minimum VUs figure to size the pool of pre-allocated users.

4. Assumptions

  • Journey mix taken from the same peak hour as the volumes.
  • Think times taken from real session data, or a stated estimate.
  • Background traffic (batch jobs, integrations, bots) included or excluded, and why.
