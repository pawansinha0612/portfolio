JMeter cheat sheet

The flags, functions and settings you look up every week, on one page. Written for JMeter 5.6.x. Print it (Ctrl/Cmd + P, the menu and buttons are hidden) or keep the tab open next to the GUI.

Command line

jmeter -n -t plan.jmx -l results.jtl -e -o report/          # run + HTML report
jmeter -n -t plan.jmx -l results.jtl -f -Jusers=50 -q env/staging.properties
jmeter -g results.jtl -o report/                               # report from an existing JTL
jmeter -n -t plan.jmx -R host1,host2 -Gusers=100 -l r.jtl -X   # distributed
HEAP="-Xms4g -Xmx4g -XX:MaxMetaspaceSize=256m" jmeter -n -t plan.jmx -l r.jtl

Environment: HEAP (default -Xms1g -Xmx1g -XX:MaxMetaspaceSize=256m), GC_ALGO, JVM_ARGS, JAVA_HOME. Stop a CLI run gracefully with bin/shutdown.sh (threads finish their current sample), or at once with bin/stoptest.sh (they talk to port 4445). JMeter exits 0 even when samples fail. Gate on results, see CI pipelines.

Elements and order

Execution order for each sampler:
  Config elements → Pre-Processors → Timers → Sampler → Post-Processors → Assertions → Listeners
Scope: an element applies to its parent and to everything under the parent.
Timers before every sampler in scope, and they add up. Variables: per thread. Properties: global.

Load maths

Thread k starts at   (k − 1) × ramp-up ÷ threads        10 threads, 100 s → every 10 s
Little's Law         threads = rate × (response time + think time)
                     20/s × (2.4 s + 18 s) = 408 threads
Iteration rate       threads ÷ (response time + think time)
Pacing               wait = max(0, pacing interval − iteration time)
Distributed          total threads = threads in plan × number of servers

Full explanations: think time and pacing, load shapes, Little's Law.
