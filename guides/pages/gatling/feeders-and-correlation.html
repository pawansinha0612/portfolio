Gatling feeders and correlation: real data, real sessions

Every virtual user logs in as test1, adds product 42 to the cart and checks out. The database serves one hot row from memory and the test passes beautifully. Feeders give each user different data. Checks with saveAs carry server-generated values from one request to the next.

The session, in one paragraph

Each virtual user has a session: a map of key to value that lives for the user's journey. Feeders put values into it. Checks with saveAs("key") put extracted values into it. #{key} in any string reads from it. Sessions are immutable, so in Java code you call session.set(...) and return the new session. Cookies are kept per user automatically, so cookie-based sessions need no work. See correlation and parameterisation in the glossary.

Feeders and their strategies

Put CSV files in src/test/resources (Maven) or src/gatling/resources (Gradle). The header row gives the session keys.

username,password

user002,Passw0rd!
StrategyBehaviourUse for
csv("f.csv") (queue)Each row once, in order. The test stops with an error when rows run out.Data that must not be reused: one-time codes, unique accounts
.circular()Back to the top when it reaches the endAccounts that can be reused
.random()A random row each time, repeats allowedSearch terms, product ids
.shuffle()Shuffled once, then each row onceUnique data in random order

Keep data files to the size the test needs, and zip big ones (.unzip() reads them). For values you can generate, such as unique order references, use an iterator feeder (shown below) instead of a giant CSV.

A full journey: login, extract, reuse

package example;

import static io.gatling.javaapi.core.CoreDsl.*;
import static io.gatling.javaapi.http.HttpDsl.*;

import io.gatling.javaapi.core.*;
import io.gatling.javaapi.http.*;
import java.util.UUID;

public class CheckoutSimulation extends Simulation {

  HttpProtocolBuilder httpProtocol = http
      .baseUrl(System.getProperty("baseUrl", "http://localhost:8080"))
      .contentTypeHeader("application/json");

  // src/test/resources/users.csv with a header row: username,password
  FeederBuilder<String> users = csv("users.csv").circular();

  ScenarioBuilder checkout = scenario("Checkout")
      .feed(users) // puts #{username} and #{password} into this user's session
      .exec(
          http("Login")
              .post("/login")
              .body(StringBody("{\"username\":\"#{username}\",\"password\":\"#{password}\"}"))
              .check(status().is(200))
              .check(jsonPath("$.access_token").saveAs("token")))
      .exitHereIfFailed() // no token, no point continuing
      .exec(
          http("List products")
              .get("/products")
              .header("Authorization", "Bearer #{token}")
              .check(jsonPath("$.items[*].id").findRandom().saveAs("productId")))
      .exec(session -> session.set("orderRef", "load-" + UUID.randomUUID()))
      .exec(
          http("Add to cart")
              .post("/cart")
              .header("Authorization", "Bearer #{token}")
              .body(StringBody("{\"productId\":#{productId},\"ref\":\"#{orderRef}\"}"))
              .check(status().is(201))
              .check(jsonPath("$.cartId").saveAs("cartId")))
      .exec(
          http("Checkout page")
              .get("/checkout")
              .check(css("input[name='csrf']", "value").saveAs("csrf")))
      .exec(
          http("Pay")
              .post("/checkout")
              .header("Content-Type", "application/x-www-form-urlencoded")
              .formParam("csrf", "#{csrf}")
              .formParam("cartId", "#{cartId}")
              .check(status().is(200)))
      .exec(session -> {
        // Plain Java for debugging: print what this user extracted
        System.out.println("cart " + session.getString("cartId") + " for " + session.getString("username"));
        return session;
      });

  {
    setUp(checkout.injectOpen(constantUsersPerSec(5).during(60)))
        .protocols(httpProtocol)
        .assertions(
            global().failedRequests().percent().lt(1.0),
            details("Pay").responseTime().percentile(95.0).lt(800),
            forAll().responseTime().percentile(99.0).lt(2000));
  }
}
  • jsonPath("$.access_token").saveAs("token") extracts the token, and every later request sends Bearer #{token}.
  • findRandom() picks one of the ids, so users don't all buy the same product.
  • css("input[name='csrf']", "value") reads a hidden form field from HTML.
  • exitHereIfFailed() stops a user whose login failed, instead of sending a string of 401s that pollute the results.
  • The System.out.println is for debugging only. Remove it before a real run: printing from thousands of users costs CPU on the load generator.

Check cookbook

package example;

import static io.gatling.javaapi.core.CoreDsl.*;
import static io.gatling.javaapi.http.HttpDsl.*;

import io.gatling.javaapi.core.*;
import io.gatling.javaapi.http.*;
import java.time.Duration;
import java.util.Iterator;
import java.util.Map;
import java.util.UUID;
import java.util.function.Supplier;
import java.util.stream.Stream;

public class ChecksSimulation extends Simulation {
  HttpProtocolBuilder httpProtocol = http.baseUrl("http://localhost:8080");

  FeederBuilder<String> q = csv("users.csv");             // queue (default): fails when rows run out
  FeederBuilder<String> c = csv("users.csv").circular();  // start again at the top
  FeederBuilder<String> r = csv("users.csv").random();    // random row each time
  FeederBuilder<String> s = csv("users.csv").shuffle();   // shuffled once, then a queue

  // Generated data: a fresh unique value for every user that feeds from it
  Iterator<Map<String, Object>> orderRefs = Stream.generate(
      (Supplier<Map<String, Object>>) () -> Map.of("orderRef", "load-" + UUID.randomUUID())
  ).iterator();

  ScenarioBuilder scn = scenario("Checks and flow")
      .feed(c)
      .feed(orderRefs)
      .exec(http("Search")
          .get("/products")
          .queryParam("q", "shoes")
          .check(status().in(200, 304))
          .check(jmesPath("items[0].name").saveAs("firstName"))
          .check(jsonPath("$.items[*].id").findAll().saveAs("allIds"))
          .check(regex("\"price\":(\\d+)").find().saveAs("price"))
          .check(header("Content-Type").is("application/json"))
          .check(jsonPath("$.nextPage").optional().saveAs("nextPage")))
      .doIf(session -> session.contains("nextPage")).then(
          exec(http("Next page").get("#{nextPage}")))
      .foreach("#{allIds}", "id").on(
          exec(http("Item").get("/products/#{id}")))
      .repeat(3).on(
          pace(Duration.ofSeconds(5))   // each loop takes at least 5 s, including the request
              .exec(http("Poll").get("/health")))
      .exec(session -> {
        int price = session.getInt("price");
        return session.set("discounted", price * 0.9);  // sessions are immutable: return the new one
      });

  {
    setUp(scn.injectOpen(atOnceUsers(1))).protocols(httpProtocol);
  }
}
CheckExtracts from
jsonPath("$.a.b")JSON, JSONPath syntax
jmesPath("a.b")JSON, JMESPath syntax (faster, stricter)
css("selector", "attr")HTML
xpath("//a/@href")XML
regex("...(group)...")Anything, as text
header("Name")Response headers
status(), bodyString(), responseTimeInMillis()The response itself

After the extractor: find() (the default, first match), find(n), findAll(), findRandom() or count(). Then a validation (is, in, exists, notExists), and/or saveAs. If you add no validation, Gatling checks that the value exists. That means a missing value fails the request, unless you mark it optional().

Debugging correlation

  • Run one user (atOnceUsers(1)) until the journey works. Then add load.
  • Print the session with exec(session -> { System.out.println(session); return session; }).
  • Turn on request logging in logback-test.xml. The demo projects ship with commented-out loggers for failed and all HTTP requests.
  • Compare a failing request with the same request from the browser's developer tools. The missing value is usually a header, a cookie set by JavaScript, or a token in a redirect.
