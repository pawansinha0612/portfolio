When Locust is a good fit

  • Your team writes Python, and the test needs your own Python code: signing, fixtures, data generators, a client library.
  • You want a live web UI to change load during exploratory runs.
  • You need a protocol that isn't HTTP: any Python client library can be wrapped as a Locust user.

The trade-off: one Locust process uses one CPU core, so high load needs several processes, and Locust's users loop, which makes it a closed model unless you pace them. Weighing it up? Read k6 vs Locust, or see the k6 and Gatling guides. The theory is in the load profiles and queueing explainers.
