LoadRunner cheat sheet

The VuGen functions and settings you look up every week, on one page. Written for C-based Web - HTTP/HTML scripts in Professional Performance Engineering 26.x, most of it unchanged for many releases. Press F1 on any function in VuGen for the full reference. Print it (Ctrl/Cmd + P) or keep the tab open.

Script structure

vuser_init()   runs once per vuser at start     (login if users stay logged in)
Action()       runs every iteration              (the measured journey)
vuser_end()    runs once per vuser at stop       (logout, cleanup)
globals.h      shared #includes and global variables
Every web_* / lr_* argument list ends with LAST

lr_* functions

FunctionDoes

lr_end_transaction("T", LR_AUTO)End it. Status LR_AUTO, LR_PASS, LR_FAIL or LR_STOP
lr_start_sub_transaction("S", "T") / lr_end_sub_transaction("S", LR_AUTO)Timer nested inside transaction T
lr_set_transaction_status(LR_FAIL)Set status of open transactions
lr_get_transaction_duration("T")Seconds elapsed so far (double)
lr_think_time(5)Pause, governed by the Think Time runtime setting
lr_rendezvous("R")Wait for other vusers (rarely a good idea)
lr_output_message("x=%s", s)Write to the output/log
lr_log_message("...")Write to the vuser log only
lr_error_message("...")Write an error message
lr_exit(LR_EXIT_ITERATION_AND_CONTINUE, LR_FAIL)End the iteration (or LR_EXIT_VUSER to stop the vuser)
lr_get_vuser_ip(), lr_whoami(&id, &grp, &scid)Run-time identity

Correlation

web_reg_save_param_ex("ParamName=Token", "LB=name=\"token\" value=\"", "RB=\"",
    "Ordinal=1", "NotFound=ERROR", SEARCH_FILTERS, "Scope=Body", LAST);

web_reg_save_param_json("ParamName=Id", "QueryString=$.items[0].id",
    SEARCH_FILTERS, "Scope=Body", LAST);

web_reg_save_param_regexp("ParamName=Ref", "RegExp=ref=([A-Z0-9]+)&",
    SEARCH_FILTERS, "Scope=Body", LAST);

web_reg_save_param_xpath("ParamName=Sid", "QueryString=//SessionId",
    SEARCH_FILTERS, "Scope=Body", LAST);
ArgumentValues
LB / RBBoundaries. LB/IC= ignores case
Ordinal1, n, ALL (array P_1..P_n and P_count), RANDOM
NotFoundERROR (default) or WARNING
SaveLen, SaveOffsetSave part of the match
Scope (after SEARCH_FILTERS)All, Body, Headers (with HeaderNames=)

All web_reg_* calls register for the next request: put them before it. More in correlation.

Runtime settings summary

SettingLoad test value
PacingAt random intervals, around the interval from your workload maths
Think timeRandom percentage of recorded (e.g. 50 to 150%), or realistic values in the script
LogSend messages only when an error occurs
Browser emulationSimulate a new user each iteration, if each iteration is a new session
Download non-HTML resourcesMatch production (off if a CDN serves them)
Continue on errorOff, unless your code checks errors itself
Run logic iterationsIgnored in duration-based schedules

Vusers = target iterations per second × pacing interval (Little's Law). Example: 0.5/s × 120 s = 60 vusers. Remember Controller keeps its own copy of runtime settings per script.

Command lines

wlrun.exe -TestPath C:\s\smoke.lrs -Run -ResultName C:\r\Res_01 -InvokeAnalysis
wlrun.exe -TestPath C:\s\smoke.lrs -Run -ResultLocation C:\r -ResultCleanName Res_01

CLIControllerApp.exe -TestPath C:\s\smoke.lrs -CollateAndAnalyze -ResultName C:\r\Res_01
CLIControllerApp.exe -InputFile C:\s\run.xml -Run -OverrideLgs C:\s\lgs.txt -SilentMode

DevWeb -mode=single -iterations=3 ./script_folder      (DevWeb.exe on Windows)
DevWeb -mode=load ./script_folder

From the 26.x help: wlrun arguments are case sensitive, only one Controller runs at a time, and results are overwritten. See CI and DevOps.

Analysis quick reference

  • Filter graphs on Scenario Elapsed Time to the steady state. Exclude failed transactions from response times.
  • Check the summary's percentile setting in Tools → Options.
  • Merge graphs: Overlay (shared time axis), Tile (stacked), Correlate (y against y).
  • Look at granularity both coarse and fine before concluding there are no spikes.
